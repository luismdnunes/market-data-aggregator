* Requirements:

## Phase 2: Memory-Aware Engineering & Zero Steady-State Allocation
Focus: Custom allocators, cache locality, and avoiding the OS kernel.
Standard containers like std::list or unconfigured std::unordered_map make frequent calls to malloc/free, forcing transitions into the OS kernel that destroy deterministic latency.

* Task: Modify Phase 1 to guarantee zero dynamic heap allocations during steady-state processing (process_tick).
* Requirements:
* Implement a contiguous Arena Allocator or a fixed-size Object Pool up front.
   * Reconfigure your internal tracking structures (queues, maps, or rings) to use custom allocators that pull memory exclusively from your pre-allocated arena.
   * Apply alignas or evaluate structural padding to ensure internal data types align perfectly to standard 64-byte cache lines.
* Constraints:
* If any component attempts to call a global operator new or malloc after the initialization phase, the program must trigger an assertion or fail to compile.
* Verification: Override the global operator new to log allocations. Run your simulation loop and ensure your allocation counter remains exactly zero during the streaming phase.

## Phase 3: Lock-Free Multithreading & Hardware Synchronization
Focus: Atomics, memory barriers, and escaping false sharing.
In production systems, data ingestion occurs on a dedicated network thread, while analytical processing runs on an isolated core. Traditional mutexes cause context-switching overhead that is unacceptable for high-frequency trading.

* Task: Split your program into two decoupled execution threads: Thread A (Ingestor) and Thread B (Processor).
* Requirements:
* Implement a Single-Producer Single-Consumer (SPSC) Lock-Free Ring Buffer to pass ticks from Thread A to Thread B.
   * Utilize atomic indices with explicit std::memory_order_release and std::memory_order_acquire constraints. Do not default to seq_cst.
   * Prevent False Sharing by ensuring the producer's write-index and the consumer's read-index reside on completely distinct cache lines using std::hardware_destructive_interference_size.
* Constraints:
* Zero mutexes, condition variables, or locks are permitted in the critical data path.
* Verification: Run the program under a thread sanitizer. Ensure no data races exist and verify that throughput scales significantly compared to a traditional mutex-protected queue.

## Phase 4: Zero-Copy Compaction & Low-Level String Parsing
Focus: String views, direct memory casting, and compiler optimization.
Market feeds (such as the Nasdaq ITCH protocol or FIX protocol) deliver data as raw byte sequences. Standard string allocations or copying buffers can easily degrade throughput.

* Task: Build a high-performance string/binary parser at the front of your pipeline.
* Requirements:
* Ingest simulated network packets formatted as raw character arrays (e.g., "TICK,1719572400000000,AAPL,18525,500").
   * Use std::string_view to parse and isolate fields completely in place without creating new string allocations or copying text data.
   * Mark parsing helpers with constexpr or consteval to force the compiler to generate optimized, loop-unrolled state machines.
   * Apply [[nodiscard]] and [[likely]]/[[unlikely]] branch prediction attributes where applicable to guide compiler code generation.
* Verification: Benchmark your parser using a high-precision clock (std::chrono::high_resolution_clock). Measure the end-to-end latency from the moment a raw byte string enters the system to the moment the VWAP updates. Target an average processing budget of under 200 nanoseconds per tick.
